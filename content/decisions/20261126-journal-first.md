# 中心を開発日誌にし、発信の下書きはおまけにする

- 状態: 本人の採用（2026-11-26の会話での本人の発言）
- 決定者: 本人
- 決定日: 2026-11-26
- 先行する判断: [プロジェクトの開始](20261126-project-setup.md)の1（外への発信の文章を作る道具）を、この決定で改める
- 経緯: [構想](../deliberations/20261126-concept.md)の§6

## 本人が決めたこと

**位置づけ（本人の言葉の要約）：** ソフトウェアファクトリーによって、開発の状況を人間が理解していない。そんな開発者のための、エージェントが作る開発日誌。おまけとして、ネタポイントがたまったら、Xの投稿の文章やnoteの記事ができる。

1. **解きたい問題。** 開発がほぼ自動で進む（ソフトウェアファクトリーの状態）ため、物事は進むが、人間が何が起きたかを認知・理解していない。開発の記録が人間に残らない。
2. **中心の出力は開発日誌。** プロジェクトごとの開発の日誌を自動でつける。人間が読みやすい、きれいな文体で書く。そのための情報はAIのエージェントが集める。出力は、きれいな日誌のWebページとする。
3. **発信はおまけ。** 開発の「ネタポイント」がたまると、「そろそろXの投稿やnoteの記事が書ける」という知らせと下書きが出てくる。
4. ハッカソンの題材もこの形にする（開発を自動でXの投稿にするだけ、という形はやめる）。
